# Datasets

This document is the entry point for TinyVision data. It describes the dataset
policy, the canonical environment-centric manifest, the staging/validation
tooling, and where the current inventory lives.

> Provenance is not optional. Every external dataset must be recorded with its
> name, source, URL, licence, size, annotation format, classes, resolution,
> limitations, intended use and retrieval date before it can be used. Unknown
> or incompatible licensing means the data cannot be included. See AGENTS.md.

## Canonical manifest (`tinyvision-env-manifest`, schema_version 1)

The atomic unit is the **camera environment** (sensor + optics + viewpoint +
lighting + visible printer setup). Splits happen at environment level so that
no environment appears in more than one split — this is the primary defence
against dataset leakage. See
[`docs/research/dataset-staging-pipeline.md`](docs/research/dataset-staging-pipeline.md).

Staging layout under `datasets/staging/<dataset>/`:

```
environments/<env_id>.json       derived view, one per environment
recordings/<rec_id>.json         derived view, one per recording
manifests/env_manifest.json      canonical manifest
metadata/                        provenance, inventory, characterization
samples/<recording_id>.jsonl     one frame sample per line
review/                          review-state snapshots
```

Top-level manifest sections (all fields; `*` = required):

| Section | Key fields |
|---|---|
| `dataset`* | `dataset_id`*, `name`*, `license`*, `license_url`, `provenance`, `acquisition_method`, `retrieval_date`, `url`, `redistribution_allowed`, `training_allowed`, `evaluation_allowed`, `notes` |
| `environments[]`* | `environment_id`*, `environment_key`*, `source_dataset`*, `contributor`, `camera{}`, `view`, `printer{}`, `environment_group`, `split_assignment`, `lighting_notes`, `background_notes`, `metadata{normal_available,failure_type}` |
| `recordings[]`* | `recording_id`*, `environment_id`*, `source`*, `duration_s`, `fps`, `width`, `height`, `continuous_realtime`, `temporal_note`, `md5`, `metadata{}` |
| `samples` (jsonl) | `sample_id`*, `recording_id`*, `environment_id`*, `frame_index`, `timestamp_s`, `source_label`, `source_failure_type`, `tinyvision_label`, `tinyvision_failure_type`, `verification`, `verification_provenance` |
| `license_consents[]` | `contributor`*, `consent_date`, `training_allowed`, `evaluation_allowed`, `redistribution_allowed`, `attribution`, `preferred_credit`, `verification`, `notes` |

Controlled vocabularies (`training/tv/envdata/schema.py`):

* splits: `train`, `validation`, `external_holdout`
* labels: `normal`, `failing`
* verification states: `pending`, `verified`, `rejected`, `uncertain`
* failure types: `spaghetti`, `under_extrusion`, `stringing`, `bed_adhesion`,
  `warping`, `layer_shift`, `extrusion_error`, `other`
* views: `front`, `side`, `overhead`, `bed_mount`, `inside_chamber`, `unknown`

**Verified-label provenance rule**: `verified` labels require a provenance
prefix of `human` or `pipeline`. Provenance `source_auto` / `source` /
`vlm_only` can never set a verified label on their own.

A template is at `datasets/staging/env_manifest.example.json`; the reference
enforcement code is `training/tv/envdata/{schema,validate,split}.py`.

## Tooling

| Command | Purpose |
|---|---|
| `tv env-index --kind <trier\|bambu> --root <dir>` | build manifest/inventory from raw data |
| `tv env-validate --dir datasets/staging/<dataset>` | structural + licence/consent + leakage validation |
| `tv env-split --dir ...` | environment-level split assignment |
| `tv env-readiness` | next-training readiness gate (exits non-zero when unmet) |
| `tv review-prep` / `review-confirm` / `review-merge` | human-review workflow |
| `tv audit-dataset --data-dir ...` | image resolution/layout audit |

`tv env-validate` is deliberately non-semantic: it checks structure, identity
and leakage integrity, licensing/consent, and physical recording attributes. It
does **not** judge image semantics or label correctness (that is review).

## Current readiness

`tv env-readiness` exits **1**: the release-class gate requires 5 human-verified
failure environments (have 0) and full failure-type coverage (gaps: spaghetti
1, under_extrusion 3, bed_adhesion 2, warping 2). RC1 trained on
`source_annotation` labels and this gate was intentionally not required for it.

## Rules

1. Never mix datasets without recording provenance.
2. Never merge a `pending` label into a verified set without human review.
3. Never split at frame/recording level; split at environment level.
4. Evaluation data must stay separate from training data (no leakage).
5. Do not commit redistributable-restricted footage; track labels/manifests only.
